## Формат данных диалогов
Диалоги описываются ассетами `DialogueAsset` на основе Unity `ScriptableObject`. 
Реплики, ответы, условия, последствия и переходы редактируются в Inspector без изменения кода.

#### Создание диалога
Через меню Create → Game → Dialogue → Dialogue.

#### Структура данных
```
DialogueAsset
└── Nodes: DialogueNode[]
    └── Choices: DialogueChoice[]
        ├── Availability: DialogueConditionSet
        │   └── AnyOf: DialogueConditionGroup[]
        │       └── AllOf: DialogueCondition[]
        ├── Effects: DialogueEffect[]
        └── Destination: DialogueDestination
```

#### Диалог 
Поле | Описание
--- | ---
`Id` | Стабильный, глобально уникальный ID диалога
`DisplayName` |	Название для разработчика
`EntryNodeId` |	ID стартового узла
`Nodes` |	Список узлов диалога

#### Реплика 
Поле | Описание
--- | ---
`Id` | ID узла, уникальный внутри диалога
`EditorTitle` | Название узла для разработчика
`EditorPosition` | Позиция для будущего графового редактора
`SpeakerId` | Идентификатор говорящего
`Text` | Текст реплики
`Choices` | Ответы игрока

В текущей приведённой реализации `DialogueView` отображает `SpeakerId` напрямую как имя

#### Ответ 
Поле | Описание
--- | ---
`Id` | Стабильный ID ответа в формате node_id.choice_id
`Text` | Текст ответа игрока
`Availability` | Условия доступности
`Effects` | Последствия, выполняемые по порядку
`Destination` | Переход после выполнения последствий

Недоступные ответы скрываются интерфейсом.

#### Идентификаторы и история
Используется следующая договорённость: id ответа в каждом узле диалога складывается из id узла диалога и id ответа, соединенные через "." (знак точки)
```
DialogueAsset.Id: merchant_marked_part
DialogueNode.Id: excuse
DialogueChoice.Id: excuse.offer_private_talk
```

При выборе ответа в истории выборов сохраняется идентификатор ответа в формает `id_диалога.id_ответа`. Так как по договоренности, id узла уже содержится в id ответа, то получается полный ид ответа в и стории как `DialogueId.DialogueNodeId.DialogueChoiceId`

### Условия доступности реплик ответа

`DialogueConditionSet.AnyOf` содержит группы условий:

- между группами действует `ИЛИ`;
- внутри `DialogueConditionGroup.AllOf` действует `И`;
- пустой `AnyOf` означает отсутствие ограничений;
- пустой `AllOf` считается выполненным.

**Важно**: пустая группа среди других групп откроет ответ независимо от остальных проверок.

#### Поля условия

Поле | Назначение
--- | ---
`Type` | Тип проверки
`Key` | ID выбора, общины, информации или флага
`ExpectedValue` |	Ожидаемое булево значение
`Comparison` | Оператор сравнения отношения
`IntValue` | Значение для сравнения отношения

#### Типы условий
Type | Что проверяет
--- | ---
`ChoiceSelected` | Был ли выбран ответ с указанным ID
`CommunityReputation` |	Отношение общины
`Knowledge` |	Получена ли информация
`StoryFlag` |	Значение сюжетного флага

Для `ChoiceSelected`, `Knowledge` и `StoryFlag`:
- `ExpectedValue = true` — факт должен присутствовать или флаг должен быть включён;
- `ExpectedValue = false` — факт должен отсутствовать или флаг должен быть выключен.

Для `CommunityReputation` используются `Comparison` и `IntValue`:
Comparison | Значение
--- | ---
`Equal` | Равно
`NotEqual` | Не равно
`Greater` |	Больше
`GreaterOrEqual` |	Больше или равно
`Less` |	Меньше
`LessOrEqual` |	Меньше или равно

#### Пример: доступ к накладной
У ответа `hub.request_papers` создаётся одна группа `AnyOf` с тремя условиями `AllOf`:
Type | Key | ExpectedValue
--- | --- | ---
`ChoiceSelected` | `excuse.offer_private_talk` | `true`
`Knowledge` |	`info.merchant_manifest` |	`false`
`StoryFlag` |	`merchant.resolved` |	`false`

Ответ доступен, только если игрок предложил частный разговор, ещё не изучил накладную и не выбрал окончательный исход.

#### Последствия
`Effects` выполняются последовательно, в порядке списка.

Type |	Значение Key |	Дополнительное поле
--- | --- | ---
`ChangeCommunityReputation` |	ID общины |	`IntValue`: изменение отношения, включая отрицательное
`SetStoryFlag` |	ID флага |	`BoolValue`: новое значение
`AddKnowledge` |	ID информации |	Не требуется
`GiveQuest` |	ID задачи |	Не требуется
`OpenScreen` |	ID экрана |	Не требуется

**Важно:** одноразовые награды (например, повышение репутации у общины) нужно защищать условиями. Запись ответа в историю сама по себе не запрещает выбирать его повторно.

#### Переходы и завершение
Destination.Type |	Поведение
--- | ---
`NextNode` |	Переход к узлу из по `NodeId`
`EndDialogue` |	Завершение разговора после последствий

Для `NextNode` целевой узел `NodeId` должен существовать в том же ассете диалога.

Узел без ответов не закрывается автоматически: игрок читает реплику и нажимает кнопку завершения. Аналогично обрабатывается узел, все ответы которого недоступны.

#### Состояние прохождения
`GameState` хранится отдельно от ассета в классе Assets/Scripts/Dialogue/Runtime/GameState.cs:

Данные |	Поле в классе | Комменатрий
--- | --- | ---
История выборов |	`HashSet<string> _selectedChoices` | Записыается как `ид_диалога.ид_узла.ид_выбора`
Полученная информация |	`HashSet<string> _knowledge` | Записывается в набор как строка
Выданные задачи |	`HashSet<string> _quests` | Записывается в набор как строка
Отношение общин |	`Dictionary<string, int> _communityReputation` | Словарь, где ключ - ид общины, значение - величина репутации
Сюжетные флаги |	`Dictionary<string, bool> _storyFlags` | Словарь, где ключ - ид флага, значение - `true/false`

Повторный запуск диалога с тем же `GameState` сохраняет последствия. `Reset()` очищает состояние.

Текущий `GameState` не реализует сохранение на диск, завершение задач или инвентарь. `GiveQuest` регистрирует только факт выдачи задачи.
